# 段评联调环境（本地 mock）

> 实机一步步核对的版本见 [`DEVICE_TEST.md`](DEVICE_TEST.md)。

没有真实段评源时，用这两个文件在本地把阅读器段评全链路跑起来。

## 文件

| 文件 | 作用 |
| --- | --- |
| `mock_review_server.py` | 本地 mock 站：假小说站（详情/目录/2 章正文）+ 段评接口（列表/发帖/回复/赞踩/删除），带一个 `java.showBrowser` 页。 |
| `mock_review_source.json` | 配套书源（Legado 格式）：`ruleReview` 声明了全部动作与 `paragraphRule`，第 1 章正文里还嵌了一个内嵌图标。 |

## 用法

1. 起服务（Python 3，只用标准库）：
   ```bash
   python tool/dev/mock_review_server.py            # 默认 0.0.0.0:8765
   python tool/dev/mock_review_server.py --port 9000
   ```
2. 导入 `mock_review_source.json`（设置 → 源管理 → 导入）。
   - 桌面/模拟器：源里地址 `http://127.0.0.1:8765` 可直接用。
   - 安卓真机：把源里的 `127.0.0.1` 换成电脑局域网 IP（服务已绑 `0.0.0.0`）。
3. 打开章节：**在线浏览 → 小说 → 搜索「河岸」→ 河岸手记 → 目录 → 第一章**。

## 能验什么

| 能力 | 预期 |
| --- | --- |
| 三点菜单「段评」 | 有入口；列表 6 条（段 1/3/5 各 2 条） |
| 长按段落 → 工具栏「段评」 | 面板默认只看本段，可切「全章 / 第 N 段」 |
| 段尾气泡 | 第 1/3/5 段末尾显示气泡 + 条数（滚动与翻页两种排版都验一遍） |
| 发帖 | 发送后提示成功，列表多一条；关闭面板气泡数字 +1 |
| 回复 | 展开某条 → 回复 → 展开区出现回复内容 |
| 赞 / 踩 | 提示成功（服务端计数变化，列表数字刷新） |
| 删除 | 确认后该条消失 |
| 内嵌图标（原生气泡） | 第 2 段末尾一个小图标，点击打开「段评（源内嵌页）」页面（走 `java.showBrowser`） |
| 换章 | 第二章无段评 → 无气泡、面板显示「本章还没有段评」 |

## 注意

- 段评数据存内存，重启服务即恢复预置数据。
- mock 用「列表序号」当段评 id（`{{$.index}}`）；删除过条目后序号与 id 会错位，
  这是简化实现的已知限制，只影响「删除后再对其它条目投票/回复」的演示。
- 头像走本地 `/avatar.png`，离线可用。
- 服务日志会打印每条请求，排查「面板空/动作失败」时对照看。
